# 工作流核心、项目系统与缓存

## 1. 工作流数据模型

`WorkflowDocument` 包含 `SchemaVersion`、名称、节点列表和连接列表。`WorkflowNode` 包含唯一 ID、算子接口名、显示名、画布坐标和 JSON 参数。`WorkflowConnection` 明确记录源节点/源端口和目标节点/目标端口。

节点 ID 是实例身份，例如 `gray_2`；算子接口名是能力身份，例如 `Image.Gray`。二者不能混用。一个接口可以在图中实例化多次，每个实例拥有独立参数和缓存键。

## 2. 强类型端口

核心定义了 Mat、整数、浮点、布尔、字符串、点、线、圆、矩形、轮廓、点集、矩阵和集合等类型。端口描述符还包含名称、是否必需、本地化显示名和介绍。

连接建立前验证：

- 节点和端口是否存在；
- 方向是否为输出到输入；
- 类型是否兼容；
- 一个输入是否已经被占用；
- 是否形成自环或有向环；
- 所有必需输入是否已连接。

一个输出可以扇出到多个下游输入；一个普通输入最多接受一条边。

## 3. 拓扑执行

工作流是 DAG。验证器生成确定性拓扑顺序，执行器按顺序创建算子并提供 `NodeExecutionContext`。算子从 Context 读取输入和参数，只能为声明过的输出端口赋值一次；执行结束还会检查声明输出是否全部产生。

点击某个节点时不会默认执行整个图。执行器从目标节点逆向遍历依赖，只构建目标及其全部上游切片。这使大型画布中的无关分支不会消耗时间。

## 4. 缓存机制

每个节点的内容缓存键由以下内容组成：

```text
算子接口名
+ 按名称排序的参数 JSON
+ 每条输入端口对应的上游缓存键
+ 外部指纹（例如输入图片文件状态）
→ SHA-256
```

因此：

- 同样的图、参数和输入会命中缓存；
- 修改某节点参数只改变该节点及其下游键；
- 修改输入图片会使整条相关分支失效；
- 改动另一条无关分支不会让当前分支重算。

缓存位于项目 `images/cache`，不是全局目录。图像输出可序列化恢复，结构化数据也按算子描述符处理。执行结果记录每个节点耗时以及是否来自缓存，UI 状态栏据此反馈。

## 5. 非托管资源管理

OpenCV `Mat` 实现 `IDisposable`。`WorkflowExecutionResult` 对所有输出按引用去重后释放，避免同一个对象通过多个端口出现时被重复释放。算子异常时，执行器同时清理已经完成节点和当前节点的输出。这是工业图像应用长期运行时非常关键的稳定性设计。

## 6. 项目目录

```text
Project/
├── ProjectName.vstudio        项目元数据和入口
├── workflows/main.vflow      工作流结构
├── images/input              导入的原图
├── images/cache              节点缓存
├── images/output             图像输出
├── output                    导出和其他产物
├── models                    项目专用推理模型（非 AI 助手模型）
├── resources                 资源
├── snapshots                 保存前快照
├── generated                 生成代码
└── .project/autosave         自动保存与操作记录
```

新建项目时软件自动创建完整目录。输入图片通过导入复制到 `images/input`，工作流只保存相对路径。`ProjectPaths.ResolveInside` 拒绝绝对路径和越界路径，防止 `../` 访问项目外文件。

## 7. 保存、自动保存和操作记录

正式保存前可生成时间戳快照；正式工作流和 `.project/autosave/main.vflow` 都使用临时文件加原子替换。操作记录以 JSON Lines 追加，便于读取最近记录且不必重写整个文件。

UI 的会话撤销栈与自动化会话事务共同工作。AI 一次计划作为一个批量修改提交，因此用户可以一次撤销整个 AI 分支，而不是逐节点撤销。

## 8. 自动化 API

`IWorkflowAutomationApi` 提供：算子目录、工作流快照、批量应用、撤销和执行。它是未来脚本、AI、Web、外部集成的稳定入口。关键字段 `expectedRevision` 防止并发覆盖，`requestId` 防止网络重试重复创建节点。

## 9. C# 导出

代码生成器先使用同一注册表验证工作流，再按拓扑顺序生成节点调用、参数和连接逻辑。导出到项目 output/generated 目录，并可自动打开文件夹。生成代码是便于继续开发的起点，不等于自动包含所有生产环境异常处理、相机生命周期和业务协议。
