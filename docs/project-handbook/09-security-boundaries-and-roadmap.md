# 安全、产品边界与演进方向

## 1. 已实现的安全边界

### 项目文件

- 工作流只接受项目相对路径；
- 组合路径必须仍位于项目根目录；
- 保存使用临时文件和原子替换；
- Web 文件读取只开放白名单目录；
- 图片上传限制扩展名、大小并做解码验证。

### AI

- 模型输出只解析严格 JSON；
- 只允许有限 Graph Action；
- 算子、端口、参数、必需输入、重复输入和环全部校验；
- revision 冲突拒绝旧计划；
- 默认建议模式需要用户确认；
- 远程配置加密；
- 本地服务默认回环地址。

### Web

- Production 缺少令牌拒绝启动；
- 通过 HTTPS 反向代理或 Tunnel 暴露；
- 项目目录隔离；
- 上传和读取边界在服务器执行。
- 损坏项目会记录诊断日志；共享项目加载不继承单个请求的取消令牌。

### Runtime

- 输入源、触发和队列属于运行平台，不进入普通算子图；
- 每帧通过 `Input.RuntimeFrame` 注入并继续由现有工作流校验和执行器处理；
- 队列容量有上限，停止和丢弃帧会释放图像资源；
- 厂商相机、PLC、结果上传和长期记录不是 V2.0 已实现功能。

## 2. 不能过度承诺的内容

- 不是经过认证的计量软件；
- 不是机器安全控制器，不能替代 PLC 安全回路；
- 单张图片通过不代表算法对所有现场条件有效；
- 本地插件不是沙箱；
- 当前 Web 令牌不是完整多租户身份系统；
- 自动生成 C# 不是一键生成完整产线应用；
- 接口存在不代表每个高级算子已有生产级实现；
- AI 建议不能替代视觉工程师验收。
- V2.0 不支持 Android/iOS，也不承诺任意 Linux 发行版。

## 3. 威胁模型中的关键风险

| 风险 | 当前缓解 | 后续增强 |
| --- | --- | --- |
| 恶意工作流路径 | 项目根路径校验 | 签名项目、内容扫描 |
| 恶意模型输出 | 白名单动作和强校验 | 策略版本、审计、权限级别 |
| 恶意插件 DLL | 只加载清单并校验目录 | 发布者签名、信任商店、隔离进程 |
| 远程 API Key 泄露 | DPAPI/AES-GCM 加密 | 系统凭据库、密钥轮换 |
| Web 未授权访问 | 令牌、HTTPS | OIDC、RBAC、项目 ACL |
| 大文件/资源耗尽 | 上传上限、目标切片、缓存 | 配额、超时、作业队列、监控 |
| 算法误判 | 可观察流程和参数 | 标注集、指标门禁、版本审批 |

## 4. 工业化路线建议

### 第一阶段：工程稳定

- 完成高频算子的空图、通道、尺寸和参数边界；
- 增加运行超时、取消、相机重连和日志诊断；
- 对项目迁移、崩溃恢复和缓存清理建立策略；
- 建立插件签名与版本兼容流程。

### 第二阶段：算法质量

- 为核心场景建设标注数据集；
- 报告 Precision、Recall、F1、长度误差和节拍；
- 参数版本与项目版本关联；
- 建立光照、材质、姿态和批次分层回归。

### 第三阶段：团队与平台

- Web 接入 OIDC、用户、角色、项目权限和审计；
- 任务队列、资源配额和多实例协调；
- 算子/插件市场、签名、兼容矩阵和更新机制；
- 工作流模板、审批和发布渠道。

### 第四阶段：现场集成

- 相机 SDK、PLC/机器人/IO、MES 和结果协议；
- 设备状态机、报警、配方切换和故障恢复；
- GPU/CPU 性能策略和边缘设备部署；
- 生产数据留存、追溯和隐私合规。

## 5. 面向客户的正确表达

建议说：“当前版本提供可视化算法设计、OpenCV 执行、缓存、导出、Web 和受控 AI 规划的完整工程框架；针对具体产线，我们会使用客户数据完成参数、精度、节拍和异常场景验证。”

不建议说：“所有算子都是工业级”“AI 能自动解决任何视觉问题”“无需标定就能测毫米”“Web 已经支持任意规模多用户”。
