# 算子体系与视觉实现

## 1. 算子由“契约”和“执行”组成

`OperatorDescriptor` 描述接口名、中文名、英文名、分类、输入端口、输出端口、参数、用途、限制和关键词；`IVisionOperator` 负责实际执行。UI、AI 检索、验证器、代码生成和 Web 目录都读取同一描述符，避免每个入口维护不同的算子定义。

新增算子的标准步骤是：

1. 定义稳定接口名，例如 `Threshold.Otsu`；
2. 定义强类型输入和输出；
3. 定义参数类型、默认值和范围；
4. 实现 `IVisionOperator.ExecuteAsync`；
5. 为多语言名称、用途和限制补充资源；
6. 补充执行、边界、缓存和代码生成测试。

## 2. 算子类别

目录覆盖输入、图像处理、滤波、增强、阈值、分割、形态学、边缘、Blob、轮廓、几何、定位、直线/圆、变换、图像运算、统计、测量、标定、逻辑、集合、显示、AI 和输出等类别。菜单只显示本地化名称，属性区显示接口名，既照顾普通用户，也方便熟悉 OpenCV 的开发者定位能力。

## 3. 多输入与多输出

每个逻辑输入都必须有独立连接点。例如模板匹配需要搜索图像和模板图像，二者不能共用一个端口。轮廓查找同时输出绘制后的图像、轮廓集合和数量；通道拆分拥有多个图像输出；统计节点可同时输出图像和数值。

这使“结果预览”和“后续计算”可以并行：图像端口用于展示或保存，结构化端口用于测量、逻辑和其他节点。

## 4. 结果显示规则

- 算子输出图像时直接显示图像；
- 轮廓、圆、线等几何结果通常绘制回输入图像；
- 纯数值或字符串输出时，结果区显示可用的输入/结果图，并叠加结构化摘要；
- 多输出节点在属性区列出所有端口，执行摘要显示 Count、Length、Score 等值。

## 5. 裂纹组合流程示例

默认裂纹数量与像素长度需求使用可观察的通用阶段：

```text
加载图像
→ 灰度化
→ 高斯模糊
→ 黑帽（突出暗色细长区域）
→ Otsu（自动二值分割）
→ 闭运算（连接小间断）
→ 查找轮廓
→ 细长目标路径统计
```

最后的 `Contour.PathMetrics` 根据面积、长度、细长度和最大数量筛选候选，输出图像、数量、估算像素路径长度、轮廓总周长和文字摘要。它是通用流程末端，不负责前面的裂纹分割。

`Defect.CrackMeasure` 是针对特定长横向暗裂纹的专项基线，只有用户明确要求专用或单算子方案时才使用。单图成功不能推广为所有材质、方向和光照的精度保证。

## 6. 实现成熟度分层

对外介绍时应把算子分为三层：

- **完整执行型**：常用颜色、滤波、阈值、形态学、轮廓、基本运算、保存等已经直接调用 OpenCV 并有集成测试；
- **基础实现型**：部分定位、测量、标定和高级几何已有可运行基础逻辑，但参数、鲁棒性和精度需要面向场景继续完善；
- **接口/预览型**：部分高级 AI、集合或复杂工业节点主要提供稳定端口、参数和基础预览，为后续实现预留兼容结构。

“目录里存在节点”不应被描述成“已经达到生产级工业算法”。

## 7. 工业化时需要补充什么

- 基于真实相机、镜头、光源和节拍建立数据集；
- 定义误检、漏检、测量误差和处理时间指标；
- 对不同材质、姿态、噪声、曝光和批次拆分验证；
- 增加相机断线、超时、空帧和恢复机制；
- 固化参数版本、标定版本和审批记录；
- 对关键算子进行 SIMD/GPU、内存复用或异步流水优化。

## 8. 像素与物理量

任何 `PixelLength`、像素距离或像素面积都只在图像坐标系中成立。要得到毫米值，需要相机标定、畸变校正和像素到世界坐标映射；若目标不在同一平面，还要处理透视和深度变化。软件提供相应标定接口，但生产计量必须使用可追溯标定件和误差评估。
