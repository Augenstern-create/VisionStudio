# 项目全景与产品价值

## 1. 项目定位

Vision Studio 面向工业视觉方案的设计、验证、沟通和复用。它把传统的“写一段 OpenCV 代码、运行、改参数、再运行”变成图形化工作流：每个节点代表一个算子实例，端口代表有类型的数据，连接表示数据依赖，属性面板负责参数，结果面板负责图像和结构化数值展示。

典型使用者包括：

- 需要快速验证检测思路的视觉工程师；
- 需要理解算法组成、但不希望从零阅读代码的项目或工艺人员；
- 需要沉淀标准流程、导出 C# 或接入自动化系统的开发团队；
- 需要在服务器统一运行视觉流程的内部团队；
- 希望通过本地大模型辅助选择算子和搭建流程的用户。

## 2. 它解决的核心问题

传统视觉开发常见问题是算法步骤隐藏在代码调用顺序里、参数散落、输入输出难追踪、局部结果不容易观察、修改后经常全量重算、方案沟通依赖开发者口头解释。Vision Studio 对应给出以下机制：

| 问题 | Vision Studio 的处理方式 |
| --- | --- |
| 算法链不可见 | 使用节点和连接展示数据流 |
| 接错数据或重复输入 | 强类型端口和工作流校验 |
| 参数修改代价高 | 点击节点执行上游切片，内容键缓存精确失效 |
| 图像与数值分离 | 节点可同时输出预览图和结构化结果 |
| 项目难迁移 | `.vstudio` + `.vflow` + 项目相对路径 |
| 只能在某个 UI 中使用 | Core、CLI、Web、自动化 API 复用同一模型 |
| AI 容易误操作 | 建议模式、动作白名单、一次事务提交、用户确认 |
| 模型包太大 | AI Provider、llama.cpp、GGUF 独立插件化 |
| 验证流程难以持续运行 | Runtime 直接读取 `.vstudio`，统一采集、触发、队列和结果映射 |

## 3. 主要功能

- 新建、打开、自动保存、快照、操作记录和 `.vstudio` 文件关联；
- 可平移网格画布、节点拖动、多输入多输出、正交圆角连线、宽命中、线路右键分支操作；
- 中文/英文资源、深色/浅色/渐变主题和 VS Code 风格工作台；
- 图像输入、颜色、滤波、增强、阈值、形态学、轮廓、定位、变换、统计、测量、标定、逻辑、显示和 AI 等算子类别；
- 点击节点执行当前节点及全部上游，展示图像、字符串和测量端口；
- 项目级磁盘缓存，参数、输入文件或上游变化时只重算受影响部分；
- 工作流验证、CLI 执行和 C# 源码导出；
- Web 项目管理、上传、服务端 OpenCV 执行、预览、撤销和导出；
- 本地/远程/标准版本地模型管理，独立项目与模型对话上下文；
- AI 根据 IMG 编号或节点名规划可检查的多阶段流程，经确认后应用。
- 独立 Runtime 随桌面安装包交付，支持图片、文件夹、视频、EmguCV 相机、模拟输入和单次/连续检测。

## 4. 与常见替代方案的区别

### 与手写 OpenCV 代码相比

手写代码自由度最高，适合最终深度优化；Vision Studio 更强调可视化验证、参数探索、团队沟通和流程资产化。两者不是互斥关系：工具可以导出 C#，也允许团队把验证后的算法进一步工程化。

### 与低代码平台相比

本项目不是通用表单或业务自动化平台。其端口类型、算子目录、执行器、缓存和预览都围绕图像、几何和测量数据设计，重点是视觉数据流的正确性和可观察性。

### 与“AI 直接生成算法代码”相比

Vision Studio 不执行模型生成的任意代码。模型只能从已注册算子中选择，并生成有限 Graph Action；宿主展开、验证和执行。这牺牲了一部分开放性，但显著提升了可控性、可撤销性和可测试性。

## 5. 项目当前成熟度

基础工作流、项目系统、桌面编辑、Runtime、缓存、代码生成、CLI、Web 服务链路、AI 插件协议和测试体系已经形成完整闭环。当前更适合算法原型、内部工具和工程验证。若用于产线，需要针对具体相机 SDK、外部触发、光源、节拍、上传系统、异常恢复、标注数据和测量精度进行专项验证，并完善部分高级算子的工业实现。

## 6. 一句话卖点

“让 OpenCV 视觉算法像工程图一样可见、可调、可验证，并让 AI 只能在安全的工作流接口内帮助搭建方案。”
