# 演示讲稿与常见问答

## 1. 十分钟演示流程

### 第 1 分钟：定位

“这是一个工业视觉算法工作流工具。中央画布表达 OpenCV 数据流，左侧选择算子或 AI，右侧查看结果与参数。核心引擎独立于 UI，同一项目可由桌面、Web、CLI 和自动化 API 使用。”

### 第 2～3 分钟：项目与画布

打开 `samples/DemoProject`，指出 `.vstudio` 是项目入口，`.vflow` 是工作流。展示网格平移、节点、不同类型端口和多输出。说明连接建立前会检查端口、重复输入和环。

### 第 4～5 分钟：执行与缓存

点击一个中间节点，展示只执行该节点及上游；再次点击观察缓存命中。修改黑帽或阈值参数，说明只有该节点和下游失效。强调缓存保存在项目目录，不是隐藏的全局状态。

### 第 6～7 分钟：结构化结果

点击轮廓/路径统计节点，展示图像预览和 Count、PixelLength、Summary。主动说明像素长度不是毫米，需要标定才能换算物理尺寸。

### 第 8～9 分钟：AI

切换 AI 面板，指出已有 IMG-01 和 IMG-02。输入“处理 IMG-02，测量裂纹数量和像素长度”。展示建议中的节点、参数、连接和结果节点；强调 AI 没有操作鼠标，也没有生成可执行代码。点击应用后，新分支通过同一 Core API 保存、执行且可撤销。

### 第 10 分钟：多形态与边界

说明桌面用于本地开发，Web 在服务器执行 OpenCV，CLI 用于自动化；AI 模型独立下载。最后说明当前是完整工程框架，具体产线精度仍需客户数据、光学方案和标注验收。

## 2. 技术问答

### Q：为什么工作流必须是 DAG？

A：DAG 可以在执行前确定拓扑顺序，阻止循环依赖，并让内容缓存沿上游键传播。当前版本聚焦图像数据流，不提供循环和状态机；需要视频时序或控制逻辑时，应在更高层加入帧循环，而不是让单帧图出现环。

### Q：为什么不直接用 Python？

A：Python 很适合算法探索，但本项目还要处理跨平台桌面、Web、安装、强类型接口、长期资源管理、代码生成和企业集成。.NET 让这些能力统一；OpenCV 算法本身仍由原生库执行。

### Q：缓存如何知道上游变了？

A：每个节点键包含自己的类型和参数，也包含每个输入对应的上游缓存键。任一上游变化会递归改变下游键；无关分支的键不变。

### Q：一个输出能连接多个节点吗？

A：可以，输出允许扇出。一个输入默认只能有一条连接，避免含义不确定。

### Q：项目 JSON 会不会被写坏？

A：保存采用临时文件加原子替换，正式保存前可生成快照，另有 autosave。仍建议使用版本控制和备份。

### Q：AI 为什么有时候输出错误 JSON？

A：本地小模型可能受输出 Token、上下文和指令遵循能力影响。系统使用紧凑计划、三次修正和严格校验；最终失败时不会应用无效计划，并把错误作为可复制对话消息显示。

### Q：AI 是怎么确保处理 IMG-02 而不是 IMG-01？

A：UI 先把 `[IMG-02]` 解析成真实节点 ID；解析优先明确编号，重复显示名不能覆盖它。Agent 再强制把新管线来源绑定到该 ID；建议和保存后的首条连接都有自动化测试。

### Q：模型看图了吗？

A：只有 Profile 声明视觉能力且存在匹配 mmproj 时，模型才会收到预览图。即使看图，模型只负责理解和规划，最终测量仍由 OpenCV 执行。没有 mmproj 时应明确称为文本规划。

### Q：为什么模型不直接生成 C#？

A：任意代码难以安全验证，也难撤销和可视化。Graph Action 的自由度较小，但每个节点、端口和参数都能检查。工作流确认后可以再由受控生成器导出 C#。

### Q：插件能否完全沙箱化？

A：当前不能。插件 DLL 是本机受信任代码，`AssemblyLoadContext` 主要解决加载和版本边界，不是安全沙箱。正式生态需要签名、来源和可能的进程隔离。

### Q：Web 为什么不开放 5080？

A：使用 Cloudflare Tunnel 或 Nginx 时，Kestrel 只监听 127.0.0.1。公网流量通过 HTTPS 入口转发，直接开放 5080 只增加攻击面。

### Q：能否多用户同时编辑？

A：当前有 revision 冲突保护，但鉴权和会话设计面向内部单租户。真正多人协作还需要用户身份、项目 ACL、操作合并/锁和审计。

### Q：能否部署到 Android？

A：核心代码可复用，但桌面 UI 不能直接变成稳定 APK。需要移动入口、触控布局、存储权限、Android OpenCV runtime 和真机测试。当前手机访问优先使用响应式 Web。

### Q：140+ 算子都能用于产线吗？

A：不能这样表述。目录是能力契约集合，常用图像处理算子较完整，部分高级节点是基础实现或接口。产线采用哪些算子，应以场景数据、精度、异常和节拍测试为准。

### Q：如何增加一个新算子？

A：定义 Descriptor、强类型端口和参数，实现 `IVisionOperator`，补充中英文名称与限制，并增加执行、缓存、代码生成和边界测试。所有 UI 和 AI 目录会从同一注册表获得它。

### Q：这个项目最关键的技术资产是什么？

A：不是某一个 OpenCV 调用，而是统一的强类型工作流模型、可验证自动化 API、内容缓存、项目格式、跨入口复用，以及把不可信 AI 计划约束到普通工作流事务中的架构。

## 3. 产品问答

### Q：适合哪些项目？

A：视觉方案验证、算法教学/沟通、内部工艺工具、标准流程模板、服务器集中执行和后续 C# 工程化。

### Q：不适合哪些项目？

A：未经专项开发直接承担安全控制、法定计量、高并发多租户云服务，或希望 AI 无监督自动决定生产参数的场景。

### Q：商业化重点是什么？

A：核心算子工业化、相机/PLC/MES 集成、数据集与指标体系、插件签名生态、团队权限、日志审计、代码签名和长期支持。

## 4. 被问到未知问题时的回答方法

先区分对方问的是“框架是否支持”“当前实现是否存在”“是否达到生产精度”还是“是否经过现场验收”。可以回答框架支持接口，但不要自动推导为算法成熟；可以说明当前测试通过，但不要推导为所有环境精度保证。必要时回到本手册第 09、10 章给出验证条件。
