# AI 工作流连线与排版规范

## 目标

AI 生成的流程必须先保证端口语义和拓扑完整，再追求视觉整齐。模型输出只是候选计划，任何缺少必需输入、重复占用输入或形成环的计划都不能写入项目。

## 端口基数

| 端口 | 允许连接数 | 说明 |
| --- | ---: | --- |
| 必需输入 | 恰好 1 | AI 新增节点提交时必须已连接 |
| 可选输入 | 0 或 1 | 有明确用途时才连接 |
| 输出 | 0～N | 输出允许分支给多个下游节点 |

画布上显示输出圆点不代表已经存在连接。一个节点有多个输出端口是接口能力；只有实际绘制的线才是连接。未被消费的结果输出可以保持空闲。

## 连线规则

1. 连接必须从输出端口指向输入端口，类型相同；`Any` 只用于接口确实声明为通配类型的情况。
2. 同一个输入端口最多一条连接。禁止相同边重复出现，也禁止两个输出同时占用同一输入。
3. 一个输出可以合法分支。例如加载图像同时连接灰度化和预览节点。
4. 同一对节点可以有多条线，但必须连接不同且必要的输入。例如 `Blob.Contours` 到 `Contour.PathMetrics` 同时传递 `Image` 和 `Contours` 是合法多输入，不是重复线。
5. 多输入算子的每个必需输入都要按名称和类型连接，不能只接图像而漏掉模板、轮廓、掩膜、点或直线数据。
6. 不得为了“用完所有输出”而连接无消费需求的 `Count`、`Threshold`、`Summary` 等结果端口。
7. 禁止自连接和有向环。上游不能依赖自己的下游结果。
8. AI 不得覆盖已有输入连接；需要替换时必须先通过明确的断开动作，并作为同一事务校验。
9. 最终结果节点必须能从指定输入图像沿有向路径到达，不能生成孤立子图。

## 自动组合规则

`add_pipeline` 展开时按以下优先级选择端口：

1. 端口名称相同且类型兼容；
2. 唯一的同类型端口；
3. 无唯一匹配时拒绝计划，要求模型明确指定，不猜测多输入语义。

展开完成后只保留标准 `add_node` 和 `connect_nodes` 动作，并执行最终完整性校验。模型返回的紧凑流程不能绕过连接数量上限和端口校验。

## 排版规则

1. 数据流默认从左向右，拓扑层级每级间隔 280 px。
2. 同一层的分支从上向下排列，行间距至少 210 px。
3. 新流程以用户指定的源节点为原点，第一处理节点放在源节点右侧。
4. 节点不得与既有节点重叠；发生冲突时优先向下移动，不把节点插入算子栏或属性栏区域。
5. 主链保持同一水平线；只有分支或汇合节点使用垂直转折。
6. 合法的多输入平行线应进入各自端口，不能在中途交叉或遮住节点标题。
7. 自动排版只改变坐标，不改变节点、参数或连接，并作为同一批 AI 操作保存和撤销。

## 校验阶段

| 阶段 | 校验内容 |
| --- | --- |
| JSON 解析 | 动作白名单、字段完整、动作数量 |
| AI 计划 | 节点实例 ID、接口 ID、端口存在性、类型、输入唯一性 |
| AI 最终图 | 所有 AI 新增节点必需输入恰好一条、无孤立新增节点、目标可达 |
| 核心工作流 | 重复输入、未知端口、类型冲突、环 |
| 执行前 | 目标节点及其依赖闭包完整 |

任何阶段失败都必须保持 Graph revision、节点、连接和项目文件不变。不能在第三次重试失败后应用残缺计划。

## 自动化测试

- 缺少必需输入：拒绝，项目不变。
- 同一输入连接两次：拒绝，项目不变。
- 一个输出连接两个不同下游：允许。
- 多输入算子缺一个输入：拒绝。
- 同一上游向同一多输入节点传递不同类型数据：允许。
- 类型不兼容、自连接、环、未知端口：拒绝。
- 七阶段组合流程：节点 X 坐标严格递增，主链从左向右。
- 执行失败或计划重试耗尽：不产生部分节点或孤立连接。
