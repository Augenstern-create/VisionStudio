# Vision Studio 项目运行平台边界

## 项目边界

- 运行入口是 `.vstudio` 文件或只包含一个 `.vstudio` 文件的目录。
- 算法定义来自项目的 `mainWorkflow`，运行器不维护工作流副本。
- 运行参数来自 `.vflow`；采集和结果映射来自项目 `runtime/profiles`。
- 远程系统凭据不得写入项目运行配置，后续使用软件级加密连接配置。

## 输入边界

- 生产工作流使用一个 `Input.RuntimeFrame` 节点作为运行时图像入口。
- 相机生命周期属于 `IFrameSource`，不属于算子或 `WorkflowExecutor`。
- `Image.Load`、`Input.Camera` 和 `Input.Video` 可继续用于编辑器预览，不作为新的生产绑定。
- EmguCV 相机源只是首个 `IFrameSource` 实现，后续厂商 SDK 通过同一接口替换。

## 执行与调度边界

- 单次运行与连续运行共享同一个逐帧工作流执行入口。
- 连续调度只管理状态、触发、采集和帧队列，不修改 `.vflow` 或 `resultMappings`。
- 外部注入必须覆盖 `Input.RuntimeFrame` 声明的全部输出。
- 运行器不修改工作流，不执行动态 C#，不加载 Roslyn 编译产物。
- Runtime 执行禁用静态项目缓存，避免不同采集帧命中相同缓存键。
- 同一控制器只允许一个采集生产者和一个工作流消费者；工作流不并发执行。
- Pause 不强制中断正在执行的帧；Stop 通过取消令牌结束等待并释放设备。

## 触发边界

- `Continuous` 以采集源可提供的速度运行，并主动让出调度权避免同步源饿死消费者。
- `Timer` 的间隔范围为 1–86400000 ms。
- `Manual` 是软件手动触发，也是未来外部硬件触发的接口基线。
- 相机、循环、触发和队列均是运行平台职责，不成为普通算子。

## 输出边界

- 只有 `resultMappings` 声明的端口才是正式检测结果。
- 图像结果写入项目 `images/output/runtime` 后再交给界面显示。
- 数值、布尔值、文本和集合统一转换为可显示摘要，并保留节点、端口和单位。
- 一个配置必须指定执行目标节点；映射只能引用该目标执行切片产生的输出。
