# 算子命名与介绍规范

## 1. 目标

算子名称首先帮助使用者判断“它解决什么问题”，其次才对应 OpenCV API。中文和英文名称用于界面展示；接口名用于工作流持久化、代码生成和开发者检索，三者不得混用。

| 字段 | 示例 | 用途 | 稳定性 |
|---|---|---|---|
| 中文名称 | `索贝尔方向梯度` | 中文界面的菜单和节点标题 | 可通过语言资源改进措辞 |
| 英文名称 | `Sobel Directional Gradient` | 英文界面的菜单和节点标题 | 可通过语言资源改进措辞 |
| 接口名 | `Edge.Sobel` | 工作流、日志、代码和兼容契约 | 发布后不可直接修改 |

属性面板显示“接口名”，不额外并排显示英文名称。中文用户需要检索 OpenCV 文档时，可直接使用接口名和参数接口名。

## 2. 中文命名规则

1. 优先采用“算法限定词 + 对象或结果”，例如`坎尼边缘检测`、`轮廓矩特征`、`最小包围圆`。
2. 仅保留能区分行为的算法人名译名。不能把四个不同算子都简称为“边缘”。
3. 避免孤立术语，如“矩”“均值”“变换”。应说明作用对象，例如`轮廓矩特征`、`图像均值`、`透视变换`。
4. 不在中文名称后拼接英文函数名。OpenCV 接口通过属性面板的接口名提供。
5. 同一分类中的名称必须唯一。不同分类重名时也应尽量加对象限定词。
6. 缩写仅在行业中没有可靠中文替代且用户必须识别时使用；名称仍应提供中文语义，例如不使用`CLAHE`作为标题，而使用`局部对比度增强`。
7. 操作成对出现时使用对称词：`按位与/按位或/按位异或/按位取反`、`开运算/闭运算`、`顶帽变换/黑帽变换`。

## 3. 英文命名规则

1. 使用 OpenCV 官方算法名和英文技术术语，不使用中式直译，例如 `Canny Edge Detection`、`Contour Moments`。
2. 名称使用 Title Case；介词和短连接词可小写，例如 `BGR to HSV`。
3. API 函数名只有在它本身就是公认算法名时保留，如 `Gaussian Blur`。不直接把驼峰接口名当界面标题。
4. 方向、对象和结果必须明确，例如使用 `Sobel Directional Gradient`，而不是含糊的 `Sobel Edge`。
5. AND、OR、XOR、FFT、DFT 等标准缩写保持大写。
6. 同一分类内英文名称必须唯一，并与中文名称表达相同语义。

## 4. 介绍文本规则

每个介绍按以下顺序写 2–4 句：

1. **作用**：算子计算或产生什么。
2. **输入输出**：需要何种图像或结构化输入，产生图像还是数值/几何结果。
3. **区别**：与同类算子的关键差异和典型使用场景。
4. **约束**：通道、尺寸、点数、核大小或噪声敏感性等容易导致失败的条件。

禁止使用“执行某某算子”“用于图像处理”这类没有信息量的介绍。中文介绍使用中文标点；英文介绍使用完整句子，不混入中文参数名。

## 5. 容易混淆的边缘与梯度算子

| 中文名称 | 英文名称 | 接口名 | 主要输出 | 选择建议 |
|---|---|---|---|---|
| 坎尼边缘检测 | Canny Edge Detection | `Edge.Canny` | 细化后的二值边缘 | 需要连续、清晰的最终边缘图时使用；需要低阈值和高阈值 |
| 索贝尔方向梯度 | Sobel Directional Gradient | `Edge.Sobel` | 一阶方向梯度强度 | 需要观察水平或垂直灰度变化、计算梯度时使用 |
| 沙尔精确梯度 | Scharr Accurate Gradient | `Edge.Scharr` | 三乘三高精度一阶梯度 | 固定使用小核并重视旋转对称精度时使用 |
| 拉普拉斯边缘检测 | Laplacian Edge Detection | `Edge.Laplacian` | 无方向二阶导数响应 | 需要同时响应各方向快速变化时使用；对噪声更敏感，应先平滑 |

Sobel、Scharr 和 Laplacian 的输出本质上是导数响应，不等同于经过连接与细化的 Canny 二值边缘。

## 6. “矩”的标准解释

`Contour.Moments` 的界面名称统一为`轮廓矩特征`，英文为 `Contour Moments`。“矩”是对像素或轮廓坐标加权求和得到的数学量，不是“矩形”。

常用结果：

- `m00`：零阶空间矩，对闭合轮廓可对应面积。
- `m10/m00`、`m01/m00`：轮廓质心坐标。
- 中心矩：描述点相对质心的分布，可进一步计算方向和形状特征。

## 7. 资源与扩展规则

界面资源位于 `src/VisionStudio.App/Resources/Strings.<语言代码>.json`。新增语言时复制一份资源文件并遵循以下约定：

- 通用界面：`Welcome.*`、`Toolbar.*`、`Panel.*`、`Property.*`。
- 分类名称：`Category.<内部分类名>`。
- 算子名称：`Operator.<接口名>.Name`。
- 算子介绍：`Operator.<接口名>.Description`。
- 每个文件必须提供 `Language.DisplayName`，应用启动时会自动发现文件并加入项目页语言菜单。

缺少某个算子资源时，中文回退到描述符中文名称，其他语言回退到规范英文名称与英文介绍。资源键可以扩展，接口名不能因翻译而改变。

## 8. 评审清单

- 中文名称是否只表达一种明确行为？
- 同分类中英文名称是否唯一？
- 是否错误地把接口名或英文函数名拼在中文标题后？
- 介绍是否说明输入、输出、区别和关键约束？
- 英文是否采用官方术语和完整句子？
- 资源文件是否同时包含名称和介绍，JSON 是否可加载？
- 工作流中的 `Type` 和端口名是否保持兼容？
