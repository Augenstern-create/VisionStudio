# AI 工作流测试用例模板

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 用例 ID | `AI-E2E-XXX` |
| 需求版本 | 例如 `1.1` |
| 测试维度 | `CompositePlanning` / `AiActions` / `AiEndToEnd` 等 |
| 项目夹具 | 项目绝对路径或仓库内相对路径 |
| 输入引用 | 例如 `[IMG-01] 加载图像` |
| 模型 | Profile ID、模型文件/远程 Model ID、量化、上下文与输出上限 |
| 执行模式 | 建议 / 自动 |

外部项目必须作为只读夹具。测试将输入图片和必要工作流复制到临时项目，禁止修改原项目、缓存或输出目录。

## 用户输入

记录未经改写的自然语言需求，以及图片的指定方式（编号、节点名、选中节点或拖入卡片）。

## 预期规划策略

列出业务目标和可检查阶段，不把预期限定为某一个名称相似的专项算子。例如：预处理 → 分割 → 清理 → 特征提取 → 测量/显示。

同时记录：

- 必须出现的算子或能力；
- 可选阶段及选择理由；
- 只有用户明确指定时才允许的专项算子；
- 结果节点必须提供的结构化端口。

## 结构验收

1. 模型只返回严格 JSON 和白名单动作。
2. `operatorId` 是接口名，`nodeId` 是唯一实例 ID，二者不得混用。
3. `add_pipeline` 在提交前完全展开，持久化计划中不存在该动作。
4. 所有必需输入已连接且类型兼容；无重复输入、自环和有向环。
5. 选中的输入节点未被删除或改写。
6. `targetNodeId` 指向具有所需输出的最终节点。
7. 三次修正仍无效时不产生任何 Graph 修改。

## 执行与缓存验收

记录首次执行是否成功、预览路径、各结构化输出和耗时。数值断言应来自标注数据或明确的回归容差；没有标注时只能检查类型、有限值和合理范围。

重复执行应命中缓存。修改某一节点参数后，只允许该节点及其下游重新计算；撤销后 Graph 与缓存键应恢复一致。

## 模型与上下文验收

- 本地与远程模型分别执行或明确标记不适用；
- 不同模型/项目上下文互不串用；
- 无视觉投影模型时明确记录“文本规划”，不得宣称模型看过原图；
- 记录原始模型响应、每次拒绝原因和最终展开计划，敏感参数脱敏。

## 边界说明

说明该用例验证的是协议、工作流构成、回归结果还是算法精度。单张图片的成功不得表述为对所有光照、材质、方向和噪声条件的精度保证。
